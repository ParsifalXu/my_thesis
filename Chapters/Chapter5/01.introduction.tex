\section{Introduction}\label{sec:intro-dataloc}
The rapid evolution of artificial intelligence is reshaping every stage of the Software Development Life Cycle (SDLC), fundamentally changing how developers interact with codebases. Through natural language interfaces, developers can now gain comprehensive insight into code repositories and delegate sophisticated tasks such as code refactoring, feature implementation, and defect repair. Central to these capabilities is \textit{code localization}, which refers to the process of identifying source code snippets, ranging from individual methods to complex logic blocks, that are relevant to a natural language query within a large-scale repository. As the community pivots towards autonomous software engineering agents, effective code localization has become a critical primary bottleneck. Accurately mapping high-level functional intent to intricate implementation logic is no longer merely a retrieval problem, but a prerequisite for enabling AI systems to reliably navigate, reason about, and modify real-world software.

State-of-the-art code localization approaches can be broadly categorized into three paradigms:
embedding-based retrieval, pipeline-guided workflows, and agent-driven exploration. These
approaches have demonstrated impressive performance on issue-solving benchmarks such as
SWE-bench~\cite{swebench2024}. However, the investigation in this study identifies a fundamental yet overlooked
bias, termed the \textbf{Keyword Shortcut}.
As the primary channel through which users report software failures to maintainers, issue reports
often contain explicit debugging cues, such as stack traces, distinctive class or function names,
and even verbatim code snippets.
These \textbf{keywords} effectively serve as ``cheat sheets'', enabling localization models to
identify relevant code through lexical matching (e.g., using grep) rather than semantic reasoning.
For example, in the filtered SWE-bench Lite benchmark, 146 of the 274 instances explicitly mention
identifiers associated with the ground-truth location.
\tref{tab:keyword_shortcut-dataloc} reports the performance of LocAgent~\cite{chen-etal-2025-locagent},
a representative code localization approach.
On instances containing such keywords, LocAgent achieves improvements of 24.20, 35.22, and 29.17
Acc@1 percentage points at the file, module, and function levels, respectively, compared with
instances without keyword cues.

This performance gap exposes a key limitation of the current localization paradigms: they often
rely on lexical anchors and struggle when such anchors are unavailable or unreliable. To isolate
this missing capability, this study introduces a new diagnostic task, \textbf{Keyword-Agnostic Logical Code
Localization (KA-LCL)}, where models or agents must identify code locations satisfying explicit
logical constraints rather than naming hints. Unlike general issue-solving code localization tasks,
which can often degrade into lexical or semantic matching, KA-LCL represents a higher-order
\textit{structural reasoning} challenge. For example, a KA-LCL query may ask, \textit{``Find all
functions where: (1) the function has more than 15 parameters, and (2) the function is not an
\_\_init\_\_ method.''} Such queries are strongly constrained and leave little room for plausible
guessing. Every predicted location must meet the required constraints, and the answer set is
directly verifiable. Moreover, KA-LCL is not intended to mimic human querying behavior. Instead, it
focuses on structural reasoning which is a prerequisite for handling latent semantic mappings. In
this sense, it can be viewed as a building block for intent-driven tasks, such as
\textit{identifying complex APIs that should be refactored}.

To systematically evaluate the limitations of existing tools, this study constructs \dataset, a diagnostic benchmark for keyword-agnostic logical code localization. \dataset complements issue-solving benchmarks for localization tasks by providing a controlled setting where queries are purely logical and devoid of naming hints. It decomposes code structures to synthesize logical queries targeting structural and behavioral code patterns. The evaluation shows a sharp performance drop in state-of-the-art methods, exposing a critical \textit{reasoning gap} in current AI localization systems.


The difficulty of KA-LCL stems from two intertwined bottlenecks. \ding{182} \textbf{Without lexical anchors, localization requires searching a much larger repository context.} Existing localization methods often use identifiers as pruning signals to narrow the set of relevant files, classes, or functions. When such signals are absent, models are forced to process substantially broader structural contexts, which aggravates the \textit{lost-in-the-middle} problem. Critical logical patterns and structural constraints become submerged within long input sequences, severely impairing the system's ability to robustly retrieve and utilize them. \ding{183} \textbf{Current methods lack deterministic repository-level structural reasoning.} Although pipeline-guided LLM workflows and agentic exploration attempt to model code relationships, they often operate as probabilistic recommendation systems that generate a ranked list of likely candidates, rather than performing rigorous structural deduction. As a result, these systems fall short of providing deterministic localization or verifiable rationales.

Conceptually, code localization can be viewed as a specialized form of code search~\cite{di2023code}. Unlike general textual information, however, source code has formally defined syntax and semantics, enabling precise parsing and program analysis. This formal nature endows code with an intrinsic reasoning affordances. From a high-level perspective, an effective repository-level localization engine requires a robust intermediate representation (IR) to bridge natural language intent and implementation logic. Such an IR should effectively capture code entities, dependencies, and structural hierarchies in an interpretable and actionable form for LLM-based agents.

To overcome the aforementioned limitations, this study proposes \tooldataloc, a neuro-symbolic framework for repository-level code localization that combines LLM-based intent interpretation with rule-based deterministic Datalog reasoning. \tooldataloc first employs static analysis to extract \textbf{program facts} from the target repository, forming a structured IR that captures both elemental properties and relational dependencies. Given a natural language query, the LLM agent translates the intended constraints into a Datalog program over these facts. The program is then executed by \textbf{\souffle}, a high-performance Datalog engine, to derive the code locations that satisfy the query. To improve the reliability of LLM-generated logic programs, \tooldataloc further incorporates a synthesize-check-refine loop with parser-gated validation, semantic repair, and mutation-based intermediate-rule diagnosis. Notably, the framework is broadly applicable to declarative logic languages, including CodeQL~\cite{github:codeql}. The framework uses \souffle because it provides LLM-friendly relational syntax, avoids the integration constraints of CodeQL’s binary-only CLI and core engine, and supports rapid iterative execution of partial rules, which enables the mutation-based diagnostics to expose zero-row intermediate relations and likely over-constraining clauses.

Crucially, by offloading structural reasoning to a deterministic engine, \tooldataloc provides verifiable answer sets rather than fixed top-$n$ recommendations, while reducing execution time and token consumption. This design also enables the agent to return definitive negative responses when no matches exist, avoiding a common pitfall of probabilistic systems that hallucinate plausible but incorrect candidates.

In summary, the contributions of this chapter are as follows.

\begin{enumerate}
    \item This study identifies the \textit{Keyword Shortcut} bias in issue-solving benchmarks and introduces a new diagnostic benchmark, \dataset, for Keyword-Agnostic Logical Code Localization (KA-LCL). It contains 225 logic-intensive queries across 9 projects, along with \negset, an empty-ground-truth variant for evaluating abstention behavior.
    \item This study proposes \tooldataloc, a neuro-symbolic framework that represents repositories as program facts and synthesizes Datalog programs from natural language constraints. By delegating structural traversal and logical filtering to a deterministic reasoning engine, \tooldataloc enables verifiable repository-level localization cost-effectively.
    \item An execution-guided synthesize-check-refine mechanism is designed for LLM-generated Datalog programs, combining parser-gated validation and repair with conservative mutation-based intermediate-rule feedback. The framework is implemented as an automated end-to-end command-line tool; the tool and benchmark are available at: \url{https://anonymous.4open.science/r/DataLoc-9ACF}.
    \item \tooldataloc is evaluated against state-of-the-art localization methods. The results show that \tooldataloc performs strongly on \dataset, achieving 66.98\% precision and 58.67\% success rate at the fine-grained function level, whereas the best-performing baselines reach only 5.87\% precision and 11.73\% success rate. \tooldataloc also maintains robust abstention behavior by explicitly returning \textit{no match found} in over 70\% of \negset cases. On SWE-bench Lite, \tooldataloc remains competitive while returning concise verifiable locations instead of top-$n$ recommendations.
\end{enumerate}
