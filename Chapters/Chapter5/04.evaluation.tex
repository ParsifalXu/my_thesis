\section{Evaluation}\label{sec:eval-dataloc}

To evaluate the effectiveness and practicality of the approach, the following research questions are formulated:
\begin{enumerate}
	\item \textbf{RQ1:} How effective is \tooldataloc in keyword-agnostic logical code localization?
	\item \textbf{RQ2:} How effective is \tooldataloc for issue-based code localization?
	\item \textbf{RQ3:} How efficient is \tooldataloc compared to baselines?
    \item \textbf{RQ4:} How does each component of \tooldataloc contribute to its performance?
\end{enumerate}

\subsection{Benchmarks and Baselines}\label{sec:eval:setup-dataloc}

\textbf{SWE-bench Lite}~\cite{swebench2024} is a curated subset of SWE-bench for cost-effective evaluation of autonomous issue resolution. Each instance contains a real-world GitHub issue, repository metadata, and patch-derived ground-truth locations. Following Suresh et al.~\cite{suresh2024cornstack}, 274 of the 300 instances whose patches modify existing functions or classes are retained, and those that introduce new functions or imports are excluded, thereby focusing evaluation on localization within existing code structures.

\textbf{\dataset} is a diagnostic benchmark for KA-LCL, containing 225 logic-intensive queries across 9 projects. Each query is formulated as a composite logical proposition over code features across multiple dimensions, such as structural granularity (e.g., classes, methods), behavioral attributes (e.g., control flow, exception handling), code metrics (e.g., inheritance depth and branch count), as summarized in \tref{tab:code_dimensions-dataloc}. From the large feature-composition space induced by these dimensions, 25 representative combinations are selected and each is instantiated on 9 repositories, with only minimal query adjustments to ensure at least one valid ground-truth location.

\textbf{\negset}, a variant of \dataset, is designed to evaluate abstention capability when no valid location satisfies a query. Since this ability can be tested without using the full benchmark scale, \negset is constructed by sampling a single repository version and deliberately modifying its queries to ensure the corresponding ground-truth sets are empty. Existing methods often rely on top-$n$ ranking to maximize recall, but an ideal localization tool should not only provide well-supported answers but also explicitly abstain when no valid answer can be ascertained, thereby avoiding false positives. Such a \textit{refusal mechanism} serves as a critical metric for the robustness of autonomous agents in production environments.

\tooldataloc is compared with four state-of-the-art baselines:
\begin{itemize}[leftmargin=*]
    \item \textbf{SweRank}~\cite{reddy2025swerank} (\textit{Embedding}): It utilizes a retrieve-and-rerank architecture to identify issue locations. It employs SWERankEmbed (137M/7B parameters) to perform initial retrieval and SWERankLLM (7B/32B parameters) to rerank the results.
    \item \textbf{Agentless}~\cite{xia2024agentless} (\textit{Pipeline}): This approach employs a hierarchical filtering strategy within a procedural workflow. It progressively prunes the search space from the file level down to specific classes or functions, utilizing an LLM to rank and select candidates at each stage.
    \item \textbf{LocAgent}~\cite{chen-etal-2025-locagent} (\textit{Agentic}): It constructs a graph-based representation and sparse indexes of the project and enables an autonomous agent to perform iterative, tool-assisted retrieval.
    \item \textbf{CoSIL}~\cite{jiang2025cosil} (\textit{Agentic}): This framework focuses on structural dependency traversal through call graphs to identify implicit locations via iterative exploration. It incorporates pruning to maintain context efficiency and restrict the search to high-relevance execution paths.
\end{itemize}

All experiments were conducted on an Ubuntu 22.04.5 LTS server with an Intel Xeon Silver 4216 CPU (2.10 GHz) and 62 GB RAM. The framework was implemented in Python 3.12.11 with the \souffle 2.4 Datalog engine. \tooldataloc was evaluated using \texttt{gpt-4o-20240513} via the OpenAI API, \texttt{claude-3-5-sonnet-20241022} via AWS Bedrock, and \texttt{Qwen3-Max} via Alibaba Cloud, using a temperature of 0.3 and a maximum of 20 iterations. The SWE-bench Lite comparison in \tref{tab:comparison_isq-dataloc} additionally reports results for GPT-5.1. Baselines ran in their official environments with required dependencies for fair comparison.

\subsection{Metrics}
Localization performance is evaluated at three levels of granularity: \textit{file, module, and function}. Let $Q$ denote the set of query instances, $G_q$ the set of ground-truth locations for query $q \in Q$, and $\mathcal{P}_q$ the set of predicted locations inferred by the agent workflow. $\mathbf{1}(\cdot)$ denotes the \textbf{indicator function}, which equals $1$ if the logical condition holds and $0$ otherwise. The evaluation uses the following six metrics:

\begin{enumerate}[leftmargin=*, label=\textbf{(\arabic*)}]
    \item \textbf{Accuracy@k (ACC@k):} It measures the ability to achieve full coverage, where a success requires all ground-truth locations to be present within the top-$k$ predicted locations. When $k$ equals the length of the prediction set, this metric becomes the \textbf{Success Rate (SR)}:
    \begin{equation}
        Acc@k = \frac{1}{|Q|} \sum_{q \in Q} \mathbf{1}(G_q \subseteq \mathcal{P}_{q,k})
    \end{equation}

    \item \textbf{Recall (REC):} It represents the proportion of ground-truth locations successfully captured for each query, averaged across queries:
    \begin{equation}
        REC = \frac{1}{|Q|} \sum_{q \in Q} \frac{|G_q \cap \mathcal{P}_q|}{|G_q|}
    \end{equation}

    \item \textbf{Precision (PRE):} This metric penalizes overprediction by calculating the fraction of predicted locations that are correct:
    \begin{equation}
        Pre = \frac{1}{|Q|} \sum_{q \in Q} \frac{|G_q \cap \mathcal{P}_q|}{|\mathcal{P}_q|}
    \end{equation}

    \item \textbf{Average Jaccard Similarity (AJS):} It quantifies the overlap between the predicted and ground-truth sets, which penalizes both missing targets and redundant predictions:
    \begin{equation}
        AJS = \frac{1}{|Q|} \sum_{q \in Q} \frac{|G_q \cap \mathcal{P}_q|}{|G_q \cup \mathcal{P}_q|}
    \end{equation}

    \item \textbf{Perfect Localization Rate (PLR):} The most stringent metric, measuring the ratio of instances where the predicted set $\mathcal{P}_q$ exactly matches the ground-truth set $G_q$. A PLR of 1.0 indicates perfect localization without any extraneous noise (i.e., $AJS = 1.0$):
    \begin{equation}
        PLR = \frac{1}{|Q|} \sum_{q \in Q} \mathbf{1}(\mathcal{P}_q = G_q)
    \end{equation}

    \item \textbf{Hit Rate (HR):} The most lenient metric, measuring the ratio of instances where the predicted set $\mathcal{P}_q$ provides at least one correct location:
    \begin{equation}
        HR = \frac{1}{|Q|} \sum_{q \in Q} \mathbf{1}(\mathcal{P}_{q} \cap G_q \neq \emptyset)
    \end{equation}
\end{enumerate}
