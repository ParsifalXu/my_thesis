\subsubsection{Effectiveness on Issue-Based Localization}

\tooldataloc is evaluated on issue-based localization using SWE-bench Lite, where queries are real GitHub issues rather than synthetic logical constraints. As shown in \tref{tab:comparison_isq-dataloc}, \tooldataloc remains competitive on this standard benchmark. With Claude-3.5, \tooldataloc achieves 72.26\%, 80.66\%, and 81.02\% Acc@1/3/5 at the file level, 75.55\% Acc@5/10 at the module level, and 68.98\% Acc@5/10 at the function level.

Acc@$k$ should be interpreted together with the size of the returned candidate set. Most baselines are explicitly optimized for fixed top-$n$ recommendation: CoSIL and LocAgent typically return top-$5$ function-level candidates, Agentless returns 5 candidates regardless of issue complexity, and SweRank adopts an aggressive strategy that utilizes top-100 rankings. By comparison, \tooldataloc does not prescribe $n$ in advance and only returns an average of 2 candidate locations per issue. Although Acc@$k$ metrics are comparable, \tooldataloc's compact candidate set provides a more precise and verifiable recommendation, minimizing the overhead of downstream validation and inspection. This precision-oriented design also yields gains in resource efficiency (Details in \sref{sec:cost-dataloc}).
