This section defines the issue of code-documentation inconsistency caused by multi-parameter
constraints and provides a detailed description of the approach. An API documentation error is an inconsistency between the library source code and its API documentation. Multi-parameter constraints refer to conditional dependency relationships that exist among multiple parameters within functions or classes. If a constraint is never violated across all execution paths in the code, it is considered a benign constraint; otherwise, it indicates a potential documentation error. According to the literature~\cite{uddin2015api,zhou2017analyzing, zhu2022identifying}, API documentation inconsistency can be categorized into two types: incorrectness and incompleteness. Incorrectness refers to cases where the documentation describes behavior that is not implemented in the code, while incompleteness arises when certain code behaviors are not reflected in the documentation. Typically, incorrectness issues are considered more critical than incompleteness.

In addition, when it comes to constraint extraction, compared to single-parameter constraints, the multi-parameter constraint extraction problem can be classified into two types, as discussed in \sref{sec:eg-mpchecker}, 1) explicit constraint and 2) implicit constraint.

\toolchecker processes a repository through the three phases in \fref{fig:arch}:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Phase I: Preprocessing} separates documentation from code and associates parameter descriptions with the relevant functions (\sref{sec:preprocess-mpchecker}).
    \item \textbf{Phase II: Constraint Extraction} has two branches: the LLM-based Constraint Extractor produces documentation constraints, and the Symbolic Executor produces code path constraints (\sref{sec:extraction-mpchecker}). Code transformation prepares functions for symbolic execution, as indicated by the ``Modify'' arrow in the figure.
    \item \textbf{Phase III: Inconsistency Detection} converts the extracted constraints into expressions for comparison and applies SMT-based fuzzy constraint reasoning (\sref{sec:detect-mpchecker}). The specialized predicates and constraint conversion supporting these comparisons are described in \sref{sec:fuzzword-mpchecker} and \sref{sec:fuzzlogic-mpchecker}.
\end{enumerate}
