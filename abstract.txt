Modern software systems must continually evolve as their dependencies and requirements change. Reliable evolution requires understanding dependency risks, locating code relevant to intended changes, and maintaining consistency between code and documentation. Large Language Models (LLMs) offer new opportunities to automate these activities, but hallucinations and errors in interpreting program structure and constraints can compromise reliability. This thesis investigates reliability challenges across three phases of software evolution: environment perception, logic implementation, and artifact delivery. It develops reproducible evaluation resources alongside neurosymbolic methods that combine LLM-based interpretation with explicit program analysis and logical reasoning.

For environment perception, dependency changes can introduce failures whose effects depend on how clients use a library. This thesis presents CompSuite, a dataset of real-world Java client-library pairs exhibiting library upgrade incompatibilities. Existing tests written by client developers and automated execution enable reproducible analysis of these incompatibilities. CompSuite provides an empirical foundation for studying client-specific dependency risks and evaluating compatibility analysis techniques, including future AI-assisted approaches.

For logic implementation, reliable modification depends on locating the code relevant to the intended changes. This thesis identifies the Keyword Shortcut in issue-based localization and formalizes Keyword-Agnostic Logical Code Localization. It introduces diagnostic benchmarks for evaluating localization beyond explicit identifier clues and abstention when no valid location exists. The proposed DataLoc framework uses LLMs to translate natural-language intent into Datalog queries over extracted program facts. Generated queries are iteratively checked and refined, and candidate locations are checked against source code to assess whether they satisfy the intended requirements.

For artifact delivery, code and documentation should remain consistent as software evolves. This thesis presents MPChecker, which uses symbolic execution to extract inter-parameter constraints from code and LLMs to extract corresponding constraints from documentation. A customized fuzzy constraint satisfaction framework accounts for uncertainty in the extracted constraints and detects inconsistencies between the two representations. This approach supports checking whether documented API requirements agree with their implementation.

Collectively, these contributions support reliable software evolution by connecting empirical evidence about dependency changes with explicit analysis of code and documentation. They provide complementary resources and methods across the three phases, advancing the foundations for AI-assisted software maintenance and future systems with greater autonomy.
