Modern software systems must continually evolve within interconnected dependency networks. Large Language Models (LLMs) offer new opportunities for automating this process, but hallucinations and errors in interpreting program structure and constraints can undermine reliability. This thesis investigates reliability challenges in three phases of software evolution: environment perception, logic implementation, and artifact delivery. It develops reproducible evaluation resources and neurosymbolic methods to support these phases.

For environment perception, dependency changes can introduce failures whose effects depend on how clients use a library. This thesis presents CompSuite, a dataset of 123 real-world Java client-library pairs exhibiting library upgrade incompatibilities. Existing tests from the client projects and an automated command-line interface enable single-command reproduction. CompSuite provides an empirical foundation for studying dependency risks and evaluating compatibility analysis techniques, including future AI-assisted approaches.

For logic implementation, reliable modification depends on locating the code relevant to the intended changes. This thesis identifies the Keyword Shortcut in issue-based localization and formalizes Keyword-Agnostic Logical Code Localization. It introduces diagnostic benchmarks to assess localization beyond explicit identifier clues and abstention when no valid location exists. The proposed DataLoc framework combines LLM-based intent interpretation with logical reasoning over program facts and checks retrieved candidates against source code. Experiments demonstrate higher localization precision than the evaluated baselines on keyword-agnostic queries, together with the ability to abstain when no valid match exists.

For artifact delivery, code and documentation must remain consistent as software evolves. This thesis presents MPChecker, which uses symbolic execution to extract inter-parameter constraints from code and LLMs to extract corresponding constraints from documentation. A customized fuzzy constraint satisfaction framework accommodates uncertainty in extracted constraints and detects inconsistencies between the two representations. Evaluation on Python data science libraries identified 11 inconsistencies confirmed by developers.

Together, these contributions connect reproducible evidence about dependency changes with explicit reasoning about code and documentation. They provide an empirical foundation and practical neurosymbolic methods to support more reliable software evolution.
